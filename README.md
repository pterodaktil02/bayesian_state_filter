# Bayesian State Filter for Home Assistant

Версия: **0.4.0**

[English README](README.en.md)

`bayesian_state_filter` - пользовательская интеграция Home Assistant для объединения нескольких асинхронных числовых датчиков в одну робастную оценку скрытого скалярного процесса.

В отличие от обычного усреднения, фильтр одновременно оценивает:

- уровень процесса;
- локальную скорость изменения;
- ускорение;
- рывок;
- относительное смещение каждого источника;
- эффективное среднеквадратическое отклонение каждого источника;
- доверие к каждому новому измерению;
- доверие к производным динамической модели.

Типичные применения: температура, давление, влажность, радиационный фон и другие непрерывные или квазинепрерывные величины, измеряемые несколькими источниками в совместимых единицах.

> Не путать со встроенной интеграцией Home Assistant `bayesian`: она оценивает вероятность события и формирует бинарный датчик. Этот проект оценивает непрерывное числовое состояние.

## Модель состояния

Состояние фильтра всегда имеет вид:

```text
[x, v, a, j]
```

где `x` - уровень, `v` - скорость изменения, `a` - ускорение, `j` - рывок.

Модель использует интегрированный винеровский процесс с шумом четвертой производной. Для среднего и ковариации применяется одна и та же матрица перехода с учетом доверия к производным. Это важно для численной устойчивости: плохо наблюдаемые производные не могут разогнать ковариацию через перекрестные связи.

### Доверие к производным

Для каждой производной вычисляется апостериорная z-оценка:

```text
z_d = |d| / sigma_d
```

Из нее получается вероятность того, что параметр отличен от нуля при нормальном апостериорном распределении:

```text
c(z) = erf(|z| / sqrt(2))
```

Эффективные веса иерархические:

```text
w_v = c_v
w_a = c_v * c_a
w_j = c_v * c_a * c_j
```

Поэтому всегда выполняется:

```text
1 >= w_v >= w_a >= w_j >= 0
```

Смысл простой: если скорость не наблюдается уверенно, ускорение и рывок не должны сильнее влиять на траекторию.

### Робастное объединение источников

Каждое измерение отдельно обновляет общее состояние. Источники не сводятся заранее к среднему.

Для каждого источника оцениваются:

- относительное смещение `bias`;
- эффективное среднеквадратическое отклонение `sigma`;
- типичный период обновления;
- невязка измерения;
- z-оценка невязки;
- робастный вес распределения Стьюдента;
- статистика выбросов.

Обновление по распределению Стьюдента может давать хорошо согласованному измерению вес немного выше 1 и плавно уменьшает вес выбросов.

### Обучение динамики

Параметры `q/timescale` идентифицируются по истории Recorder на естественной временной сетке процесса. Проверка качества идет на 1-2 естественных шага, а не на произвольный длинный горизонт.

RMSE используется как диагностический показатель качества идентификации, но не определяет доверие к производным. Доверие рассчитывается только из апостериорного состояния и его ковариации.

### Быстрый рестарт и контрольные точки

Состояние сохраняется в Home Assistant Store каждые **30 минут**.

Контрольная точка содержит:

- `[x, v, a, j]`;
- ковариацию `P`;
- обученные `q/timescale`;
- калибровки источников;
- диагностику характерного времени процесса;
- отметки последней обработанной истории Recorder;
- служебную версию формата.

После рестарта интеграция:

```text
загрузить контрольную точку
-> прочитать только новую часть истории Recorder
-> пропустить ее через обычный путь фильтра
-> перейти в рабочий режим
```

Полное обучение по нескольким суткам истории выполняется только если контрольная точка отсутствует, повреждена или несовместима по формату. Тяжелая калибровка источников не пересчитывается на каждом измерении: повторная оценка запускается адаптивно по состоянию монитора дрейфа.

## Калибровка источников в рабочем режиме

На каждом новом измерении выполняются обычное обновление фильтра и дешевый монитор дрейфа. Переоценка `bias/sigma` по историческому окну выполняется отдельно и адаптивно: редко для стабильных источников и чаще при признаках дрейфа.

Дрейф оценивается относительно собственного базового уровня каждого источника, а не общего фиксированного порога. Состояние планировщика сохраняется в контрольной точке.

Для фиксации общего смещения поддерживаются три режима `bias_anchor`:

- `median` - робастная привязка общего нуля по медиане смещений;
- `mean` - линейная привязка с нулевой суммой смещений;
- `passport` - абсолютная привязка по паспортной точности моделей; каждая модель дает один робастный голос независимо от числа одинаковых физических датчиков.

## Установка

Скопируйте каталог:

```text
custom_components/bayesian_state_filter
```

в:

```text
/config/custom_components/bayesian_state_filter
```

После замены Python-файлов выполните полный перезапуск Home Assistant.

YAML можно перечитать без полного перезапуска действием:

```text
bayesian_state_filter.reload
```

## Минимальная конфигурация

```yaml
sensor:
  - platform: bayesian_state_filter
    name: "Температура зала"
    ensemble:
      sources:
        - sensor.temperature_1
        - sensor.temperature_2
        - sensor.temperature_3
```

Все источники должны измерять одну физическую величину в совместимых единицах. Автоматического преобразования единиц нет.

## Рекомендуемая конфигурация

```yaml
sensor:
  - platform: bayesian_state_filter
    name: "Температура зала"

    ensemble:
      sources:
        - sensor.temperature_1
        - sensor.temperature_2
        - sensor.temperature_3
        - sensor.temperature_4
      min_sources: 2

    bayes:
      noise_model: auto
      history_days: 7
      save_every_s: 1800
      student_nu: 4
      characteristic_refit_s: 21600
      diagnostics: compact
```

Основные параметры:

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `history_days` | `7` | Глубина истории Recorder для начальной калибровки и идентификации динамики |
| `save_every_s` | `1800` | Интервал сохранения контрольной точки |
| `student_nu` | `4` | Число степеней свободы распределения Стьюдента |
| `characteristic_refit_s` | `21600` | Период повторной оценки характерного времени уровня |
| `warmup_refit_s` | `21600` | Минимальный период повторного обучения динамики, пока она еще не идентифицирована |
| `bias_anchor` | `median` | Способ фиксации общего смещения: `median`, `mean` или `passport` |
| `noise_model` | `auto` | `auto`, `gaussian` или `poisson` |
| `diagnostics` | `compact` | `compact`, `full`, `debug`, `verbose` |

## Основные атрибуты

Итоговая сущность датчика публикует, в частности:

```text
stddev
rate_per_hour
curvature_per_hour2
jerk_per_hour3

rate_weight
curvature_weight
jerk_weight

rate_z
curvature_z
jerk_z

gated_timescale_s
gated_local_rmse
gated_local_rmse_step1
gated_local_rmse_step2
```

Имена атрибутов остаются английскими как часть программного интерфейса. По смыслу:

- `rate_per_hour` - скорость изменения в час;
- `curvature_per_hour2` - ускорение в час²;
- `jerk_per_hour3` - рывок в час³;
- `rate_weight`, `curvature_weight`, `jerk_weight` - веса доверия к соответствующим производным.

Внутри модели производные хранятся в единицах времени на секунду.

Для каждого источника в `source_health` доступны:

```text
model
bias
sigma
median_dt_s
outlier_rate
last_z_score
robust_weight
```

Здесь `bias` - оцененное систематическое смещение источника, `sigma` - эффективное среднеквадратическое отклонение измерения, `outlier_rate` - доля выбросов, `robust_weight` - текущий робастный вес измерения.

Также сохраняется отдельная оценка `characteristic_time_s`. Она описывает медленную динамику уровня процесса и не обязана совпадать с `gated_timescale_s`, который относится к локальной модели в пространстве состояний.

## Практические замечания

- `bias` является относительным смещением, если не используется внешний или паспортный якорь. Без него фильтр не может определить общую систематическую ошибку всех датчиков.
- `sigma` - эффективная ошибка наблюдения общего скрытого состояния, а не паспортная точность датчика.
- Высокий `robust_weight` означает согласованное измерение, низкий - выброс или временное расхождение источника.
- Большие значения `curvature_per_hour2` или `jerk_per_hour3` сами по себе не означают аварию. Это локальные производные, пересчитанные из секунд в часы; смотреть их нужно вместе с `curvature_weight`, `jerk_weight` и локальным RMSE.
- Если динамика неразличима на фоне шума, корректное поведение - веса производных стремятся к нулю и фильтр фактически становится оценкой уровня.
