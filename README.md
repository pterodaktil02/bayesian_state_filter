# Bayesian State Filter for Home Assistant

Версия: **0.5.0-dev.38**

[English README](README.en.md)

`bayesian_state_filter` - пользовательская интеграция Home Assistant для объединения нескольких асинхронных числовых датчиков в одну робастную оценку скрытого скалярного процесса.

В отличие от обычного усреднения, фильтр одновременно оценивает:

- уровень процесса;
- локальную скорость изменения;
- ускорение;
- рывок;
- относительное смещение каждого источника;
- характерную дисперсию измерений каждого источника;
- неопределенность текущей оценки;
- доверие к производным динамической модели.

Типичные применения: температура, атмосферное и канальное давление, влажность, радиационный фон и другие непрерывные или квазинепрерывные величины.

> Не путать со встроенной интеграцией Home Assistant `bayesian`: она оценивает вероятность события и формирует бинарный датчик. Этот проект оценивает непрерывное числовое состояние.

## Модель состояния

Состояние фильтра всегда имеет вид:

```text
[x, v, a, j]
```

где `x` - уровень, `v` - скорость изменения, `a` - ускорение, `j` - рывок.

Модель использует интегрированный винеровский процесс. Вес доверия к производным применяется к прогнозу среднего, а ковариация распространяется полной кинематической матрицей. Это не дает слабо подтвержденным производным разгонять средний прогноз, но сохраняет их наблюдаемость через перекрестные ковариации.

### Производные и независимый наблюдатель

Производные `v/a/j` входят непосредственно в вектор состояния и влияют на прогноз уровня. Начиная с 0.5.0-dev.38 их рабочий вес определяется в первую очередь не исторической близостью к нулю, а согласованностью состояния байесовского фильтра с независимым наблюдателем, построенным только по прямым или объединенным измерениям.

Историческая статистика Recorder по-прежнему обучает робастные масштабы

```text
sigma_hist = 1.4826 * MAD(d)
```

но теперь они описывают прежде всего необычность текущей динамики. Реальный новый процесс может находиться далеко за пределами исторических 3-5 сигм и при этом быть корректным, если его подтверждают непосредственные наблюдения.

Независимый наблюдатель строится как робастная многомасштабная локально-полиномиальная оценка по последним точкам:

```text
короткое: >= 25 точек и >= 0.5 * характерное время процесса
среднее:   >= 40 точек и >= 1.0 * характерное время процесса
длинное:   >= 55 точек и >= 2.0 * характерное время процесса
```

Для скорости и ускорения используются согласованные оценки нескольких масштабов. Для рывка требуются две кубические оценки - на среднем и длинном окнах. Окно всегда удовлетворяет одновременно ограничениям по числу точек и по физическому времени.

Если наблюдатель надежен, для каждого порядка считается

```text
z_edge = |d_bayes - d_edge| / sigma_edge
```

и локальный вес:

```text
w = 1,                         z_edge <= 1
w = exp(-0.5 * (z_edge-1)^2),  1 < z_edge < 5
w = 0,                         z_edge >= 5
```

То есть в пределах одной сигмы наблюдателю доверяем полностью, затем вес плавно падает и на 5 сигмах становится нулевым. Большая сама по себе производная не штрафуется, если независимый наблюдатель ее подтверждает.

Высшие порядки по-прежнему наследуют штрафы низших:

```text
W_v = w_v
W_a = w_v * w_a
W_j = w_v * w_a * w_j
```

По мере потери согласованности динамики модель автоматически деградирует:

```text
x-v-a-j -> x-v-a -> x-v -> x
```

Если надежной независимой оценки для конкретного порядка пока нет, используется исторический резервный вес правдоподобия. Поэтому после рестарта или большого разрыва наблюдений фильтр остается консервативным до накопления нового непрерывного участка данных.

### Восстановление производных

Разрушительное восстановление производной выполняется не по одному необычному значению, а по устойчивому расхождению байесовской оценки и независимого наблюдателя:

```text
начать ожидание:  z_edge > 5
отменить ожидание: z_edge < 3
```

Восстановление разрешено только после как минимум пяти свежих обновлений независимого наблюдателя и не раньше одного `process_timescale_s` с момента начала кандидата. При срабатывании первая расходящаяся производная и хвост выше нее переоцениваются по независимой оценке.

Историческое восстановление по порогу 5 сигм остается запасным механизмом, когда независимой оценки нет.

### Разрывы наблюдений

Независимый наблюдатель причинный и не имеет права строить производную через участок, где процесс не наблюдался. Поэтому

```text
разрыв > process_timescale_s
=> новый непрерывный участок
```

Старая история наблюдателя больше не участвует в аппроксимации, незавершенное ожидание восстановления сбрасывается, внешние веса производных снимаются и временно используется исторический резервный вес. Само состояние байесовского фильтра при этом не сбрасывается.

История независимого наблюдателя сохраняется отдельно в контрольной точке. Если контрольная точка старая или содержит слишком мало данных, интеграция один раз добирает недостающий хвост прямых или объединенных измерений из Recorder.

## Робастное объединение источников

В многодатчиковом режиме фильтр хранит последнее валидное состояние каждого источника и на каждом новом событии строит общую оценку на текущий момент.

Для каждого источника используются:

- последнее измерение;
- `bias`;
- характерная дисперсия `sigma^2`;
- типичный период публикации `median_dt_s`;
- возраст последнего измерения.

Редкий источник не считается плохим только потому, что он публикуется редко. Пока возраст не превышает его нормальный интервал публикации, дополнительная неопределенность не начисляется. После этого растет именно дисперсия прогноза того, что источник показал бы сейчас:

```text
R_eff = R_sensor + R_age
```

Это особенно важно для батарейных и событийных датчиков: редкая публикация и точность измерения - разные свойства.

После переноса источников к одному моменту времени выполняется робастное variance-aware fusion, и уже одна общая оценка с собственной дисперсией поступает в фильтр состояния.

## Калибровка источников

### Bias

`bias` (смещение) рассматривается как медленная метрологическая характеристика. Он не переоценивается по текущей динамике процесса.

В 0.4.1 смещение оценивается по полной истории `history_days`, но только по наиболее спокойным участкам. Быстрые изменения исключаются, потому что разные датчики могут по-разному реагировать на одно физическое изменение и такая разница не является смещением нуля.

Для длинной истории используется грубая временная сетка, достаточная для оценки медленного смещения и резко снижающая стоимость недельной перекалибровки.

При применении нового набора смещений общий ноль сохраняется: перекалибровка не должна создавать искусственную ступеньку итогового уровня.

Поддерживаются три режима `bias_anchor`:

- `median` - робастная привязка общего нуля по медиане смещений;
- `mean` - линейная привязка с нулевой суммой смещений;
- `passport` - абсолютная априорная привязка по паспортной точности моделей; каждая модель дает один робастный голос независимо от числа одинаковых физических датчиков.

### Sigma

`sigma` источника также считается медленной характеристикой измерительного канала. Она обучается на длинной Recorder-истории и не переоценивается на каждом живом окне.

Для нескольких источников используется попарная калибровка с выравниванием по времени. Для единственного источника применяется локально-линейная оценка остаточного шума, не списывающая обычный локальный тренд процесса в шум измерений.

Текущая болтанка процесса не изменяет `sigma_sensor`; во время работы изменяется только дополнительная неопределенность из-за возраста измерения и итоговая дисперсия объединенной оценки.

## Идентификация динамики

В 0.4.1 шум процесса больше не выводится из одного найденного `timescale`.

Отдельно оцениваются:

```text
q_process
level_q_process
```

по ошибкам прогноза сразу на нескольких горизонтах:

```text
1, 2, 4, 8, 16, 32 естественных шага
```

Для длинной истории сохраняются несколько непрерывных фрагментов с естественным шагом публикации. Это позволяет видеть и быстрые компоненты процесса, не превращая недельную историю с частотой 1 Гц в огромную задачу.

`gated_timescale_s` теперь является вторичной диагностикой найденного шум процесса, а не управляющим параметром модели. Отдельная медленная оценка `characteristic_time_s` остается диагностической и может быть `null`, если характерное время не идентифицируется над шумом.

## Автоопределение шума

`noise_model: auto` различает стохастическое семейство и квантование как независимые свойства.

Активное семейство публикуется как:

```text
noise_model: gaussian | poisson
```

а обнаруженное квантование - отдельными параметрами:

```text
quantization_step
quantization_sigma
quantization_confidence
```

Квантование само по себе не считается признаком Poisson. Поэтому, например, целочисленный датчик давления может оставаться `gaussian`, одновременно имея `quantization_step: 1`.

Для автоматического распознавания масштабированного пуассоновского процесса используются два режима доказательства:

1. Если история покрывает достаточно широкий диапазон уровней, проверяется зависимость локальной дисперсии от уровня: `Var(X) ~ k * E[X]`. Устойчивое положительное масштабирование дисперсии дает `reason: variance_scales_with_level`.
2. Если сигнал почти стационарен и диапазона уровней недостаточно, используется моментный тест масштабированного пуассоновского процесса. Для `X = kN`, где `N` имеет распределение Poisson, выполняется `skew(X) = sigma / mean`. Детектор требует длинную положительную историю, статистически значимую положительную асимметрию и согласие наблюдаемого `skew` с `sigma/mean`. Успешный тест дает `reason: stationary_scaled_poisson`.

Если широкий диапазон уровней доступен, но дисперсия не растет вместе с уровнем, выбирается Gaussian с `reason: variance_not_level_dependent`. Отрицательные значения являются сильным аргументом против счетной модели и дают `reason: not_count_like`.

Для счетных и масштабированных счетных величин пуассоновская модель использует дисперсию, пропорциональную текущему уровню. Параметр `variance_scale` публикуется в диагностике noise model.

## Быстрый рестарт и контрольные точки

Состояние сохраняется в хранилище Home Assistant каждые **30 минут**.

Контрольная точка содержит состояние `[x, v, a, j]`, ковариацию, шум процесса, калибровки источников, отметки обработанной истории Recorder и независимую `edge_history`.

После рестарта фильтр сначала скрыто догоняет историю и только затем публикует первое состояние:

```text
загрузить checkpoint / выполнить bootstrap
-> скрыто дочитать Recorder tail
-> скрыто применить самые свежие текущие состояния источников
-> синхронизировать внутренний state с текущим моментом
-> только после этого публиковать entity
```

Провал в исходных данных во время рестарта поэтому должен проявляться как рост неопределенности, а не как искусственная ступенька уровня.

Дополнительно существует резервная публикация: если байесовская оценка уровня сильно расходится с прямым или объединенным наблюдением и одновременно есть признаки испорченной динамики или подтверждаемого смены режима, наружу временно публикуется прямое наблюдение. Сам байесовский фильтр при этом продолжает обновляться скрыто и возвращается в публикацию после устойчивого схождения.

Полная первичная инициализация выполняется только при отсутствии или несовместимости checkpoint. Тяжелые операции чтения/перекалибровки выполняются вне критического пути обработки; вычислительные части запускаются через исполнитель задач Home Assistant.

## Установка

Скопируйте каталог:

```text
custom_components/bayesian_state_filter
```

в:

```text
/config/custom_components/bayesian_state_filter
```

После замены Python-файлов выполните полный перезапуск Home Assistant.

YAML можно перечитать без полного перезапуска действием:

```text
bayesian_state_filter.reload
```

## Минимальная конфигурация

```yaml
sensor:
  - platform: bayesian_state_filter
    name: "Температура зала"
    ensemble:
      sources:
        - sensor.temperature_1
        - sensor.temperature_2
        - sensor.temperature_3
```

Все источники должны измерять одну физическую величину в совместимых единицах. Автоматического преобразования единиц нет.

## Рекомендуемая конфигурация

```yaml
sensor:
  - platform: bayesian_state_filter
    name: "Температура зала"

    ensemble:
      sources:
        - sensor.temperature_1
        - sensor.temperature_2
        - sensor.temperature_3
        - sensor.temperature_4
      min_sources: 2

    bayes:
      noise_model: auto
      history_days: 7
      save_every_s: 1800
      student_nu: 4
      characteristic_refit_s: 21600
      diagnostics: normal
```

Основные параметры:

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `history_days` | `7` | Глубина Recorder-истории для калибровки и идентификации динамики |
| `save_every_s` | `1800` | Интервал сохранения checkpoint |
| `student_nu` | `4` | Число степеней свободы распределения Стьюдента |
| `characteristic_refit_s` | `21600` | Период повторной диагностики медленного характерного времени |
| `warmup_refit_s` | `21600` | Минимальный период повторного обучения динамики |
| `bias_anchor` | `median` | `median`, `mean` или `passport` |
| `noise_model` | `auto` | `auto`, `gaussian` или `poisson` |
| `diagnostics` | `normal` | `minimal`, `normal` или `debug`; старые `compact/full/verbose` принимаются как алиасы |

### Пример `passport`

```yaml
sensor:
  - platform: bayesian_state_filter
    name: "Pressure ensemble"

    ensemble:
      sources:
        - entity_id: sensor.pressure_1
          model: bmp280_pressure
        - entity_id: sensor.pressure_2
          model: bmp280_pressure
        - entity_id: sensor.pressure_3
          model: bmp390_pressure

      models:
        bmp280_pressure:
          absolute_accuracy: 1.0
        bmp390_pressure:
          absolute_accuracy: 0.5

    bayes:
      bias_anchor: passport
```

Несколько датчиков одной модели не создают несколько независимых абсолютных голосов: семейство модели участвует в якоре один раз.

## Основные атрибуты

По умолчанию используется компактная рабочая диагностика `normal`:

```yaml
stddev: ...

filter:
  mode: tracking
  noise_model: gaussian
  noise_confidence: ...

dynamics:
  rate:
    value_per_hour: ...
    weight: ...
  curvature:
    value_per_hour2: ...
    weight: ...
  jerk:
    value_per_hour3: ...
    weight: ...
  plausibility:
    rate_sigma_per_hour: ...
    curvature_sigma_per_hour2: ...
    jerk_sigma_per_hour3: ...
    rate_mean_over_sigma: ...
    curvature_mean_over_sigma: ...
    jerk_mean_over_sigma: ...
    rate_edge_z: ...
    curvature_edge_z: ...
    jerk_edge_z: ...
    rate_edge_local_weight: ...
    curvature_edge_local_weight: ...
    jerk_edge_local_weight: ...

  recovery:
    count: ...
    process_timescale_s: ...
    edge_divergence:
      enter_sigma: 5
      cancel_sigma: 3

  edge_witness:
    process_timescale_s: ...
    gap_limit_s: ...
    segment_points: ...
    segment_span_s: ...

regime:
  candidate: false
  last_jump: ...

fallback:
  active: false

sources:
  configured: ...
  active: ...
  unhealthy: ...

last_update:
  source: ...
  innovation_z: ...
  clipped: false
  dt_s: ...
```

`*_mean_over_sigma` показывает смещение среднего обучающего распределения производной относительно ее робастного масштаба. Небольшое ненулевое значение нормально для квантованных и неравномерно дискретизированных процессов.

Режим `minimal` оставляет только наиболее важное состояние. Режим `debug` дополнительно публикует полную лабораторную диагностику: апостериорную неопределенность и z-оценки производных, калибровку, состояние источников, внутренние параметры модели шума, характерные времена, догон истории после запуска, смену режима и подробности резервного режима.

## Практические замечания

- `bias` и `sigma` - медленные параметры источника; текущая физическая динамика не должна переучивать их каждую секунду.
- В `median`/`mean` режиме общий систематический сдвиг всех источников неидентифицируем. `passport` добавляет prior, но не является физическим эталоном.
- Редкий датчик не штрафуется за сам факт редкой публикации. С возрастом увеличивается неопределенность его текущего значения.
- Исторический робастный MAD-масштаб показывает прежде всего необычность динамики, а не ее корректность.
- При надежном независимом наблюдателе вес `v/a/j` определяется согласованностью байесовской оценки и непосредственных наблюдений: полный вес до 1 сигмы, плавное гауссово падение до нуля к 5 сигмам.
- Если независимый наблюдатель временно недоступен, используется исторический резервный вес правдоподобия.
- Подтвержденный фазовый переход уровня не должен обучаться как огромные скорость, ускорение или рывок: окна через такие переходы исключаются из статистики производных.
- При потере правдоподобности динамики модель каскадно деградирует от `x-v-a-j` к `x`.
- `characteristic_time_s: null` при `insufficient_signal` - нормальный результат: фильтр не обязан придумывать характерное время там, где оно не наблюдается.
