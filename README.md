# Bayesian State Filter for Home Assistant

Версия: **0.5.0-dev.38**

[English README](README.en.md)

`bayesian_state_filter` - пользовательская интеграция Home Assistant для объединения нескольких асинхронных числовых датчиков в одну робастную оценку скрытого скалярного процесса.

В отличие от обычного усреднения, фильтр одновременно оценивает:

- уровень процесса;
- локальную скорость изменения;
- ускорение;
- рывок;
- относительное смещение каждого источника;
- характерную дисперсию измерений каждого источника;
- неопределенность текущей оценки;
- доверие к производным динамической модели.

Типичные применения: температура, атмосферное и канальное давление, влажность, радиационный фон и другие непрерывные или квазинепрерывные величины.

> Не путать со встроенной интеграцией Home Assistant `bayesian`: она оценивает вероятность события и формирует бинарный датчик. Этот проект оценивает непрерывное числовое состояние.

## Модель состояния

Состояние фильтра всегда имеет вид:

```text
[x, v, a, j]
```

где `x` - уровень, `v` - скорость изменения, `a` - ускорение, `j` - рывок.

Модель использует интегрированный винеровский процесс. Confidence gating применяется к прогнозу среднего, а ковариация распространяется полной кинематической матрицей. Это не дает слабо подтвержденным производным разгонять средний прогноз, но сохраняет их наблюдаемость через перекрестные ковариации.

### Производные и независимый edge witness

Производные `v/a/j` входят непосредственно в вектор состояния и влияют на прогноз уровня. Начиная с 0.5.0-dev.38 их рабочий вес определяется в первую очередь не исторической близостью к нулю, а согласованностью Bayesian state с независимым causal witness, построенным только по прямым raw/fused наблюдениям.

Историческая Recorder-статистика по-прежнему обучает робастные масштабы

```text
sigma_hist = 1.4826 * MAD(d)
```

но теперь они описывают прежде всего необычность текущей динамики. Реальный новый процесс может находиться далеко за пределами исторических 3-5 sigma и при этом быть корректным, если его подтверждают непосредственные наблюдения.

Edge witness строится как робастная многомасштабная локально-полиномиальная оценка:

```text
short:   >= 25 точек и >= 0.5 * process_timescale
medium:  >= 40 точек и >= 1.0 * process_timescale
long:    >= 55 точек и >= 2.0 * process_timescale
```

Для `rate` и `curvature` используются согласованные оценки нескольких масштабов. Для `jerk` требуются две кубические оценки - medium и long. Окно всегда удовлетворяет одновременно ограничениям по числу точек и по физическому времени.

Если witness валиден, для каждого порядка считается

```text
z_edge = |d_bayes - d_edge| / sigma_edge
```

и локальный вес:

```text
w = 1,                         z_edge <= 1
w = exp(-0.5 * (z_edge-1)^2),  1 < z_edge < 5
w = 0,                         z_edge >= 5
```

То есть внутри одной sigma edge-свидетелю доверяем полностью, затем вес плавно падает и на 5 sigma становится нулевым. Большая сама по себе производная не штрафуется, если независимый witness ее подтверждает.

Высшие порядки по-прежнему наследуют штрафы низших:

```text
W_v = w_v
W_a = w_v * w_a
W_j = w_v * w_a * w_j
```

По мере потери согласованности динамики модель автоматически деградирует:

```text
x-v-a-j -> x-v-a -> x-v -> x
```

Если качественного edge witness для конкретного порядка пока нет, используется исторический plausibility fallback. Поэтому после рестарта или большого разрыва наблюдений фильтр остается консервативным до накопления нового causal сегмента.

### Recovery производных

Разрушительное восстановление производной выполняется не по одному необычному значению, а по устойчивому расхождению Bayes и edge witness:

```text
ENTER grace:  z_edge > 5
CANCEL grace: z_edge < 3
```

Recovery разрешен только после как минимум пяти свежих edge-обновлений и не раньше одного `process_timescale_s` с момента начала кандидата. При срабатывании первая расходящаяся производная и хвост выше нее переоцениваются по witness hints.

Исторический 5-sigma recovery остается fallback-механизмом, когда независимого witness нет.

### Разрывы наблюдений

Edge witness причинный и не имеет права строить производную через участок, где процесс не наблюдался. Поэтому

```text
gap > process_timescale_s
=> новый edge-сегмент
```

Старая edge-история больше не участвует в fit, незавершенный recovery grace сбрасывается, external derivative weights снимаются и временно используется historical fallback. Сам Bayesian state при этом не сбрасывается.

Edge history сохраняется отдельно в checkpoint. При старом или недостаточном checkpoint интеграция один раз добирает недостающий direct/fused хвост из Recorder.
## Робастное объединение источников

В multi-source режиме фильтр хранит последнее валидное состояние каждого источника и на каждом новом событии строит общую оценку на текущий момент.

Для каждого источника используются:

- последнее измерение;
- `bias`;
- характерная дисперсия `sigma^2`;
- типичный период публикации `median_dt_s`;
- возраст последнего измерения.

Редкий источник не считается плохим только потому, что он публикуется редко. Пока возраст не превышает его нормальный интервал публикации, дополнительная неопределенность не начисляется. После этого растет именно дисперсия прогноза того, что источник показал бы сейчас:

```text
R_eff = R_sensor + R_age
```

Это особенно важно для батарейных и event-driven датчиков: редкая публикация и точность измерения - разные свойства.

После переноса источников к одному моменту времени выполняется робастное variance-aware fusion, и уже одна общая оценка с собственной дисперсией поступает в state filter.

## Калибровка источников

### Bias

`bias` рассматривается как медленная метрологическая характеристика. Он не переоценивается по текущей динамике процесса.

В 0.4.1 bias оценивается по полной истории `history_days`, но только по наиболее спокойным участкам. Быстрые изменения исключаются, потому что разные датчики могут по-разному реагировать на одно физическое изменение и такая разница не является смещением нуля.

Для длинной истории используется грубая временная сетка, достаточная для оценки медленного bias и резко снижающая стоимость недельной перекалибровки.

При применении нового набора bias общий ноль сохраняется: перекалибровка не должна создавать искусственную ступеньку итогового уровня.

Поддерживаются три режима `bias_anchor`:

- `median` - робастная привязка общего нуля по медиане смещений;
- `mean` - линейная привязка с нулевой суммой смещений;
- `passport` - абсолютная prior-привязка по паспортной точности моделей; каждая модель дает один робастный голос независимо от числа одинаковых физических датчиков.

### Sigma

`sigma` источника также считается медленной характеристикой измерительного канала. Она обучается на длинной Recorder-истории и не переоценивается на каждом живом окне.

Для нескольких источников используется time-aligned pairwise calibration. Для единственного источника применяется локально-линейная оценка остаточного шума, не списывающая обычный локальный тренд процесса в measurement noise.

Текущая болтанка процесса не изменяет `sigma_sensor`; в runtime изменяется только дополнительная неопределенность из-за возраста измерения и итоговая дисперсия fused ensemble.

## Идентификация динамики

В 0.4.1 process noise больше не выводится из одного найденного `timescale`.

Отдельно оцениваются:

```text
q_process
level_q_process
```

по ошибкам прогноза сразу на нескольких горизонтах:

```text
1, 2, 4, 8, 16, 32 естественных шага
```

Для длинной истории сохраняются несколько непрерывных фрагментов с естественным cadence. Это позволяет видеть и быстрые компоненты процесса, не превращая недельную 1 Hz историю в огромную задачу.

`gated_timescale_s` теперь является вторичной диагностикой найденного process noise, а не управляющим параметром модели. Отдельная медленная оценка `characteristic_time_s` остается диагностической и может быть `null`, если характерное время не идентифицируется над шумом.

## Автоопределение шума

`noise_model: auto` различает стохастическое семейство и квантование как независимые свойства.

Активное семейство публикуется как:

```text
noise_model: gaussian | poisson
```

а обнаруженное квантование - отдельными параметрами:

```text
quantization_step
quantization_sigma
quantization_confidence
```

Квантование само по себе не считается признаком Poisson. Поэтому, например, целочисленный датчик давления может оставаться `gaussian`, одновременно имея `quantization_step: 1`.

Для автоматического распознавания scaled-Poisson используются два режима доказательства:

1. Если история покрывает достаточно широкий диапазон уровней, проверяется зависимость локальной дисперсии от уровня: `Var(X) ~ k * E[X]`. Устойчивое положительное масштабирование дисперсии дает `reason: variance_scales_with_level`.
2. Если сигнал почти стационарен и диапазона уровней недостаточно, используется моментный тест scaled-Poisson. Для `X = kN`, где `N` имеет распределение Poisson, выполняется `skew(X) = sigma / mean`. Детектор требует длинную положительную историю, статистически значимую положительную асимметрию и согласие наблюдаемого `skew` с `sigma/mean`. Успешный тест дает `reason: stationary_scaled_poisson`.

Если широкий диапазон уровней доступен, но дисперсия не растет вместе с уровнем, выбирается Gaussian с `reason: variance_not_level_dependent`. Отрицательные значения являются сильным аргументом против счетной модели и дают `reason: not_count_like`.

Для счетных и масштабированных счетных величин Poisson-like модель использует дисперсию, пропорциональную текущему уровню. Параметр `variance_scale` публикуется в диагностике noise model.

## Быстрый рестарт и контрольные точки

Состояние сохраняется в Home Assistant Store каждые **30 минут**.

Контрольная точка содержит состояние `[x, v, a, j]`, ковариацию, process noise, калибровки источников, Recorder watermarks и независимую `edge_history`.

После рестарта фильтр сначала скрыто догоняет историю и только затем публикует первое состояние:

```text
загрузить checkpoint / выполнить bootstrap
-> скрыто дочитать Recorder tail
-> скрыто применить самые свежие текущие состояния источников
-> синхронизировать внутренний state с текущим моментом
-> только после этого публиковать entity
```

Провал в исходных данных во время рестарта поэтому должен проявляться как рост неопределенности, а не как искусственная ступенька уровня.

Дополнительно существует publication fallback: если Bayesian level сильно расходится с прямым raw/fused наблюдением и одновременно есть признаки испорченной динамики или подтверждаемого regime change, наружу временно публикуется direct observation. Сам Bayesian filter при этом продолжает обновляться скрыто и возвращается в публикацию после устойчивого схождения.

Полный bootstrap выполняется только при отсутствии или несовместимости checkpoint. Тяжелые операции чтения/перекалибровки выполняются вне hot path; вычислительные части запускаются через executor Home Assistant.

## Установка

Скопируйте каталог:

```text
custom_components/bayesian_state_filter
```

в:

```text
/config/custom_components/bayesian_state_filter
```

После замены Python-файлов выполните полный перезапуск Home Assistant.

YAML можно перечитать без полного перезапуска действием:

```text
bayesian_state_filter.reload
```

## Минимальная конфигурация

```yaml
sensor:
  - platform: bayesian_state_filter
    name: "Температура зала"
    ensemble:
      sources:
        - sensor.temperature_1
        - sensor.temperature_2
        - sensor.temperature_3
```

Все источники должны измерять одну физическую величину в совместимых единицах. Автоматического преобразования единиц нет.

## Рекомендуемая конфигурация

```yaml
sensor:
  - platform: bayesian_state_filter
    name: "Температура зала"

    ensemble:
      sources:
        - sensor.temperature_1
        - sensor.temperature_2
        - sensor.temperature_3
        - sensor.temperature_4
      min_sources: 2

    bayes:
      noise_model: auto
      history_days: 7
      save_every_s: 1800
      student_nu: 4
      characteristic_refit_s: 21600
      diagnostics: normal
```

Основные параметры:

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `history_days` | `7` | Глубина Recorder-истории для калибровки и идентификации динамики |
| `save_every_s` | `1800` | Интервал сохранения checkpoint |
| `student_nu` | `4` | Число степеней свободы распределения Стьюдента |
| `characteristic_refit_s` | `21600` | Период повторной диагностики медленного характерного времени |
| `warmup_refit_s` | `21600` | Минимальный период повторного обучения динамики |
| `bias_anchor` | `median` | `median`, `mean` или `passport` |
| `noise_model` | `auto` | `auto`, `gaussian` или `poisson` |
| `diagnostics` | `normal` | `minimal`, `normal` или `debug`; старые `compact/full/verbose` принимаются как алиасы |

### Пример `passport`

```yaml
sensor:
  - platform: bayesian_state_filter
    name: "Pressure ensemble"

    ensemble:
      sources:
        - entity_id: sensor.pressure_1
          model: bmp280_pressure
        - entity_id: sensor.pressure_2
          model: bmp280_pressure
        - entity_id: sensor.pressure_3
          model: bmp390_pressure

      models:
        bmp280_pressure:
          absolute_accuracy: 1.0
        bmp390_pressure:
          absolute_accuracy: 0.5

    bayes:
      bias_anchor: passport
```

Несколько датчиков одной модели не создают несколько независимых абсолютных голосов: семейство модели участвует в якоре один раз.

## Основные атрибуты

По умолчанию используется компактная рабочая диагностика `normal`:

```yaml
stddev: ...

filter:
  mode: tracking
  noise_model: gaussian
  noise_confidence: ...

dynamics:
  rate:
    value_per_hour: ...
    weight: ...
  curvature:
    value_per_hour2: ...
    weight: ...
  jerk:
    value_per_hour3: ...
    weight: ...
  plausibility:
    rate_sigma_per_hour: ...
    curvature_sigma_per_hour2: ...
    jerk_sigma_per_hour3: ...
    rate_mean_over_sigma: ...
    curvature_mean_over_sigma: ...
    jerk_mean_over_sigma: ...
    rate_edge_z: ...
    curvature_edge_z: ...
    jerk_edge_z: ...
    rate_edge_local_weight: ...
    curvature_edge_local_weight: ...
    jerk_edge_local_weight: ...

  recovery:
    count: ...
    process_timescale_s: ...
    edge_divergence:
      enter_sigma: 5
      cancel_sigma: 3

  edge_witness:
    process_timescale_s: ...
    gap_limit_s: ...
    segment_points: ...
    segment_span_s: ...

regime:
  candidate: false
  last_jump: ...

fallback:
  active: false

sources:
  configured: ...
  active: ...
  unhealthy: ...

last_update:
  source: ...
  innovation_z: ...
  clipped: false
  dt_s: ...
```

`*_mean_over_sigma` показывает смещение среднего обучающего распределения производной относительно ее робастного масштаба. Небольшое ненулевое значение нормально для квантованных и неравномерно дискретизированных процессов.

Режим `minimal` оставляет только наиболее важное состояние. Режим `debug` дополнительно публикует полную лабораторную диагностику: posterior uncertainty и z-score производных, calibration, source health, noise-model internals, timescales, startup catch-up, regime-change и fallback details.

## Практические замечания

- `bias` и `sigma` - медленные параметры источника; текущая физическая динамика не должна переучивать их каждую секунду.
- В `median`/`mean` режиме общий систематический сдвиг всех источников неидентифицируем. `passport` добавляет prior, но не является физическим эталоном.
- Редкий датчик не штрафуется за сам факт редкой публикации. С возрастом увеличивается неопределенность его текущего значения.
- Исторический robust-MAD масштаб показывает прежде всего необычность динамики, а не ее корректность.
- При валидном edge witness вес `v/a/j` определяется согласованностью Bayes и непосредственных наблюдений: полный вес до 1 sigma, плавное Gaussian-падение до нуля к 5 sigma.
- Если edge witness временно недоступен, используется historical plausibility fallback.
- Подтвержденный фазовый переход уровня не должен обучаться как огромные скорость/ускорение/jerk: окна через такие переходы исключаются из статистики производных.
- При потере правдоподобности динамики модель каскадно деградирует от `x-v-a-j` к `x`.
- `characteristic_time_s: null` при `insufficient_signal` - нормальный результат: фильтр не обязан придумывать характерное время там, где оно не наблюдается.
